# ADR-006: Desktop UI with Tauri 2 and Svelte, separate from the daemon

Date: 2026-10-26 · Status: accepted

## Context

Phase 6 needs a UI: a library of the user's wallpapers (Workshop items and
their own files) with previews, search and filters (P15), a properties panel
built from each wallpaper's `project.json`, per-monitor choice, playlists,
pause-policy presets (P17), cost reports (P12) and settings. WE's UI is a
270 MB CEF app that runs all the time (P13). lumend already serves a local
IPC protocol (`lumen-ipc`, named pipe) used by the `lumen` CLI.

## Decision

- **`apps/lumen-ui`: Tauri 2, front end in Svelte built by Vite** (user's
  choice over plain JS and a native Rust toolkit). The webview is the system
  WebView2, already required for web wallpapers; nothing is bundled.
- **A separate process that talks to lumend over `lumen-ipc`**, like the CLI.
  The daemon starts without it, keeps no UI state, and keeps running when the
  UI closes; the UI starts lumend if it is not running.
- **Reading the library is the UI's job** (`crates/lumen-library`: Steam
  libraries and Workshop folders, the user's own folders, `project.json`
  metadata, previews). The daemon receives only paths and choices.
- **Everything the user changes lives in the daemon's `state.json`**: what
  plays on which monitor, property overrides (over WE's own choices),
  playlists, policies. The CLI and UI are views onto it.
- **The tray icon belongs to lumend** (native, no webview), so it exists
  while the wallpaper does; its menu opens the UI.
- The Svelte sources and their npm dependencies are a build input of
  `lumen-ui` only; the rest of the workspace stays Rust-only. Built assets
  are not committed.

## Consequences

- Node.js and npm are needed to build `lumen-ui` (development and CI).
- Daemon features (per-monitor content, overrides, playlists, presets) are
  usable from the CLI before the UI exists, and testable without it.
- Packaging (MSI, winget), code signing and auto-update are decided when the
  release is prepared.
